## 致命的・重要課題（優先度A）

### A-1. 過量チェックのレースコンディション

- **箇所**: `functions/src/intakes.ts` 46-67行
- **問題**: 累計の読み取り→書き込みがFirestoreトランザクション未保護。複数タブや高速連打で過量チェックをバイパスできる
- **例**: limitPerDay=3 の薬に2タブ同時で takenUnits=2 を送信 → 両方 previousTotal=0 → 両方 isOverdose:false → 合計4錠記録
- **修正**: Firestoreトランザクション化、またはカウンタードキュメント導入

### A-2. 「飲んだ」ボタンにダブルタップ防止がない

- **箇所**: `IntakeForm.tsx` 132-137行
- **問題**: `disabled` 属性なし。送信中に連打で複数記録される。ボタンサイズも小さい（py-1.5）
- **修正**: 薬ごとの submitting state + disabled 制御 + ボタン拡大（py-3以上）

### A-3. 記録の取り消しができない

- **箇所**: Intake に DELETE/UPDATE エンドポイントなし
- **問題**: 誤タップで記録された場合、修正不可。誤記録が累計に影響し以後の過量判定が狂う
- **修正**: ソフトデリート（`cancelled: true`）+ Toast UI での即時取り消し

### A-4. Webアプリの入口ページがない

- **箇所**: 未実装
- **問題**: ドメインにアクセスしても直接ログイン画面。サービス説明・機能紹介・スクリーンショットなどのランディングページがない。初見ユーザーが「何のアプリか」分からない
- **修正**: ログイン前に表示するLP的なトップページを追加

### A-5. PWA manifest に `display: 'standalone'` 未設定

- **箇所**: `astro.config.mjs` 13-22行
- **問題**: デフォルト `browser` のため、ホーム画面追加してもブラウザUIが表示される。PWAとして機能しない
- **修正**: `display: 'standalone'`, `start_url: '/'`, `background_color: '#ffffff'` 追加

### A-6. PC版UIがのっぺらい

- **箇所**: 全ページ共通
- **問題**: max-width制限なし or レスポンシブ考慮不足。PC幅で開くとカードが横いっぱいに広がり、余白のない平坦なUIになる
- **修正**: `max-w-md mx-auto` 等でコンテンツ幅を制限するか、PC向けレイアウト（サイドバー/2カラム等）を検討。スマホ特化と割り切るならそれを明示

## 重要課題（優先度B）

### B-1. クライアント/サーバーの日付ずれ

- **箇所**: `intakes.ts` 43行 vs `IntakeForm.tsx` 11行
- **問題**: 端末時刻とサーバー時刻の差で 0:00 JST 前後に日付不整合。過量チェックが別日に分散する可能性
- **修正**: POST レスポンスでサーバー側 dateKey を返し、クライアントはそれを使用

### B-2. 過量警告が他の薬の記録後も消えない

- **箇所**: `IntakeForm.tsx` 100行付近
- **問題**: overdoseMsg は一度セットされると、別の薬を記録してもクリアされない
- **修正**: `handleTake` 冒頭で `setOverdoseMsg('')` を追加

### B-3. 錠数入力の number input が危険

- **箇所**: `IntakeForm.tsx` 124-129行
- **問題**: `max` 属性なし（999999錠でも入力可）、`parseInt` で NaN になるケース（空文字）のガードなし、モバイルでスクロール操作により意図せず値が変わる
- **修正**: +/- ステッパーボタンに置き換え + NaN ガード + max 制限

### B-4. firebase.json の SPA リライトが Astro static と矛盾

- **箇所**: `firebase.json` 6行
- **問題**: `"rewrites": [{ "source": "**", "destination": "/index.html" }]` で全パスが `/index.html` にリライトされる。Astro static は各ページが個別 HTML として生成されるため矛盾
- **修正**: リライトルール削除（静的サイトは Firebase Hosting が自動で `/medications/index.html` を解決する）

### B-5. firestore.indexes.json が存在しない

- **箇所**: プロジェクトルート
- **問題**: 複合インデックスの定義がコードに含まれない。デプロイ再現性なし
- **修正**: 必要なインデックスを `firestore.indexes.json` として管理

### B-6. フロントエンドのエラーハンドリング不足

- **箇所**: `IntakeForm.tsx` useEffect 内、`MedicationList.tsx` handleDelete
- **問題**: Promise.all 失敗時に catch なし（薬一覧が空表示）。削除失敗時もサイレント
- **修正**: try-catch + エラー state 表示

### B-7. i18n ハードコード

- **箇所**: `LogList.tsx` 33行（「ホームから記録する →」）、63行（「累計」）
- **問題**: 日本語がハードコードされており、英語/インドネシア語ユーザーに日本語が表示される
- **修正**: i18n キーに置き換え

## 改善課題（優先度C）

### C-1. セキュリティヘッダーの欠如

- **箇所**: `firebase.json`
- **問題**: CSP、X-Frame-Options、X-Content-Type-Options 等のヘッダーなし
- **修正**: `firebase.json` の `headers` セクションに追加

### C-2. 入力値の上限バリデーション不足（バックエンド）

- **箇所**: `medications.ts`, `intakes.ts`
- **問題**: name に数MB文字列、limitPerDay に MAX_SAFE_INTEGER、takenUnits に超大数でも受け入れる
- **修正**: name 100文字以下、limitPerDay 99以下、takenUnits 99以下のバリデーション追加

### C-3. express.json のボディサイズ制限なし

- **箇所**: `functions/src/index.ts` 31行
- **問題**: デフォルト 100KB。明示的制限がない
- **修正**: `express.json({ limit: '10kb' })`

### C-4. レート制限がない

- **箇所**: `functions/src/index.ts`
- **問題**: 有効トークンを持つユーザーが大量リクエストで Firestore コスト攻撃可能
- **修正**: MVP段階では暫定対応、将来的に Firebase App Check

### C-5. users.ts で毎回 getUser() を呼んでいる

- **箇所**: `functions/src/users.ts` 27-37行
- **問題**: verifyIdToken で既に email が取得できるのに、再度 Auth API を呼んでいる。不要な API コール
- **修正**: verifyToken ミドルウェアで decoded.email もリクエストに付与

### C-6. テストカバレッジが極端に低い

- **箇所**: `functions/src/tests/`
- **問題**: 純粋関数（calcOverdose）のみテスト。HTTP ハンドラーの統合テスト皆無。medications.test.ts は実質プレースホルダー
- **修正**: 最低限、各エンドポイントの正常系・異常系テストを追加

### C-7. 累計表示の視認性が低い

- **箇所**: `IntakeForm.tsx` 119行
- **問題**: `text-xs text-gray-400` で「0/3 錠」。高齢者・視力が弱い人には読みにくい
- **修正**: プログレスバー化 + フォントサイズ拡大

### C-8. タッチターゲットが全般的に小さい

- **箇所**: 薬リストの編集/削除ボタン、言語切替ボタン等
- **問題**: Apple HIG / Material Design の推奨最低44x44pt を満たしていない
- **修正**: ボタンに p-2 以上のパディング

### C-9. 服薬完了状態の可視化がない

- **箇所**: `IntakeForm.tsx`
- **問題**: 全ての薬を飲み終えた状態と、まだ飲んでいない状態の視覚的区別がない
- **修正**: 全薬完了時のメッセージ/スタイル表示

### C-10. Workbox runtimeCaching 未設定

- **箇所**: `astro.config.mjs`
- **問題**: API レスポンスのオフラインキャッシュなし。オフライン時にフレンドリーなメッセージもない
- **修正**: vite-plugin-pwa の workbox.runtimeCaching で API キャッシュ設定
