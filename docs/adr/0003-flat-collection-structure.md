# ADR-0003: サブコレクション不使用（フラット構造）

## ステータス
承認

## コンテキスト
Firestore はサブコレクション（`users/{userId}/medications`）をサポートするが、ObatLog は個人向けアプリであり、データ構造はシンプルに保ちたい。

## 決定
全コレクション（`users`, `medications`, `intakes`, `dailyCounts`）をトップレベルに配置し、各ドキュメントの `userId` フィールドでフィルタリングする。

## 理由
- クエリがシンプル（`where('userId', '==', uid)` で統一）
- コレクション間の結合やバッチ処理が容易
- Admin SDK 経由のアクセスのため、サブコレクションによるセキュリティ分離のメリットがない（ADR-0001 参照）
- データ移行やエクスポートが単純になる

## 代替案
- **サブコレクション（`users/{userId}/medications` 等）**: ユーザーごとにデータが自然に分離されるが、コレクショングループクエリが必要になる場面で複雑化する。マルチテナント要件がないため過剰

## 影響
- 全クエリに `userId` フィルタが必須（漏れるとデータ漏洩のリスク）
- Functions 側で `userId` チェックを徹底する必要がある
