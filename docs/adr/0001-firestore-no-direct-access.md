# ADR-0001: Firestore クライアント直接アクセス禁止

## ステータス
承認

## コンテキスト
ObatLog は服薬記録・OD防止を扱うアプリであり、データの整合性とセキュリティが重要。
Firestore はクライアントから直接読み書きできるが、Security Rules だけで複雑なバリデーションを担保するのは難しい。

## 決定
`firestore.rules` で全ドキュメントへの読み書きを `allow read, write: if false;` で全拒否し、全操作を Firebase Functions (Admin SDK) 経由に限定する。

## 理由
- バリデーションロジックを Functions に一元化でき、ルールの肥大化を防げる
- idToken 検証・userId チェックを API 層で統一的に行える
- OD判定（dailyCounts との照合）など、複数コレクションにまたがるロジックをトランザクションで安全に実行できる

## 代替案
- **Security Rules で細かくアクセス制御**: コレクションごとにルールを記述する方法。バリデーションが分散し、ルールのテスト・保守コストが高い
- **クライアント直接書き込み + Cloud Functions トリガー**: 書き込み後に検証する方式。不正データが一時的に存在するリスクがある

## 影響
- 全データ操作に API コールが必要（クライアント SDK の直接クエリは使えない）
- Functions のコールドスタートがレイテンシに影響する場合がある
